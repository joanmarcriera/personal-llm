# Handoff — 2026-09-06 — Dependency upgrade sweep

## What changed
- Nothing applied. `pyproject.toml` declares all ~85 direct dependencies with unbounded
  `>=X.Y.Z` specifiers (no upper bound) — e.g. `pandas>=2.2.3`, `chromadb>=0.5.11`.
  Running `uv lock --upgrade` under these specifiers is not a safe minor/patch-only
  operation: it re-resolved 316 packages and jumped several across major versions
  (large ML-adjacent stack — gradio, various transformers/tokenizer-family packages,
  etc. moved multiple majors). That's outside this sweep's mandate (minor/patch only,
  majors get a note instead), so it was reverted (`git checkout -- uv.lock`) rather
  than committed.

## Verified
- Working tree confirmed clean again after revert.

## What's left
- This repo needs upper-bounded specifiers (e.g. `>=2.2.3,<3`) before a minor/patch-only
  `uv lock --upgrade` is meaningful — otherwise every upgrade run risks a silent major
  bump. Consider adding bounds repo-wide, or handling individual packages with
  `uv lock --upgrade-package <name>` once desired target versions are chosen by hand.
- Also on branch `fix/ruff-lint-672` (not `main`) — re-run this sweep once that lands,
  from a clean `main`.
